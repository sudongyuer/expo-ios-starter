# expo-ios-starter

- Template for iOS apps built with a pnpm workspace, Expo Router, React Native, and one
  local Expo Swift module. iOS only, permanently.
- Stack: Expo SDK 57 (Expo Router, Expo Modules), React Native 0.86, TypeScript, pnpm
  workspace, vitest. Minimum iOS 26.0; Xcode 26.4 or later. Read the versioned docs of
  the installed Expo / React Native release before writing code; do not rely on memory.
- Lint: `expo lint` (ESLint 9 flat config from `packages/config/eslint.js`, which also
  enforces the native-import and `packages/core` boundaries). Format: Prettier.

## Boundaries

- Do not write Android code, stubs, or build scripts, do not keep Android sources alive
  in vendored dependencies, and do not weigh Android portability when choosing a design.
- All first-party native code and native UI live in `apps/mobile/modules/starter-kit`,
  registered through `StarterKitModule`. Do not create separate bridge packages.
- After adding or removing files under `modules/starter-kit/ios`, run `pnpm pods`:
  CocoaPods snapshots the podspec glob at install time, so new files are not compiled
  until then. Never edit `Pods.xcodeproj` by hand.
- `ios/` is generated by prebuild and is not committed. Persist native changes in
  `app.config.ts`, config plugins, or the kit; never only in generated files. App
  extensions are generated by config plugins too.
- Never disable code signing (`CODE_SIGNING_ALLOWED=NO` and similar), including Simulator
  builds. It strips entitlements: the app still launches, then Keychain fails and
  dependent features silently return empty. If signing fails, fix signing.
- Credentials live in the Keychain through the kit. Never commit tokens, certificates,
  `.env` files, transcripts, or private service configuration.
- Preserve user edits. Before destructive operations (revert, reset, delete, force-push),
  inspect the working tree and ask for confirmation.

## Layout

All paths under `apps/mobile/src` unless noted.

- `app`: route files only; screens stay thin. `pages`: `definePage` definitions.
- `features`: domain logic and data shapes; never imports `app`, `pages`, or `components`.
- `components`: shared UI. `navigation`: shared Stack options. `theme/tokens.ts`:
  colors, spacing, radii, type. `i18n`: setup; text in `apps/mobile/locales/{zh-Hans,en}.json`.
- `services`: the only code that talks to the network or device services; verify mode
  swaps it for `services/fixtures`. `debug/scenes.ts`: Debug scenes.
- `lib/presentation`: React bindings for `present()`. `lib/ui-verify.ts`: verify-mode flags.
- `packages/core`: platform-neutral TypeScript. Must not import React Native, Expo, or `apps/*`.
- `packages/config`: shared tsconfig and lint config.
- Add a state library only when a feature needs one, decided in that feature's spec.

## UI baseline

- Apple's Human Interface Guidelines are the primary requirement and acceptance
  standard; product references inform behavior only.
- Use real platform controls. When React Native cannot reach system quality, write
  Swift in the kit. Never imitate a control or native effect with RN views.
- Screens use tokens, never raw values: semantic colors, system blue for actions,
  neutral backgrounds; preserve dark mode and increased contrast.
- Preserve native navigation, safe areas, VoiceOver labels, and 44 pt touch targets.
  Respect system text sizing; no special layouts for the largest accessibility sizes
  unless a spec asks.
- Each tab is a NativeTabs tab with its own native Stack and navigation bar; no custom
  headers. Drill-down pushes with system back; sheets are for transient flows.
- Navigating rows stay selected until return, deselect with the return transition, and
  reselect if the pop is cancelled; action rows deselect at once (as `GroupedList` does).
- Views that own keyboard layout natively are not wrapped in RN keyboard avoidance.

## Motion

- Add motion with the `animate-expo` skill: gate first, then numbered options with a
  recommendation. Frequent interactions, tab switches, the keyboard, and stack
  transitions keep platform behavior.
- Reanimated only (`npx expo install react-native-reanimated react-native-worklets`;
  worklets is explicit because `autoInstallPeers` is off). No `setState` from gesture
  or scroll handlers. Animate `transform` and `opacity`; reduced motion drops movement
  and keeps opacity and color.
- Haptics fire with their visual, once per action, never alone. Judge feel on a
  Release build on a device.

## Pages and native APIs

- Pages with stable URLs use the Router. Flows that return a result are `definePage`
  pages opened with `await present(page, params)`, which resolves `completed` or
  `cancelled`. Do not add a second modal manager.
- `present` params live in the presentation store; only `presentationId` enters the URL.
  Back, swipe, and unmount settle as `cancelled`; every presentation settles exactly
  once. Presentations are not durable deep links.
- Native APIs come only from `modules/starter-kit/src/index.ts`, never
  `requireNativeModule`. Facade, view wrappers, and Swift share feature directories.
  Remove subscriptions in effect cleanup; UIKit work runs on the main queue.
- Fault injection, runtime internals, and demos live only on the development-only Debug
  page, reached from Settings. Product screens show only state the user can act on.

## Data integrity

- Persist the user's input before sending it, and keep drafts across failures.
- An acknowledgement means delivered, not completed; show progress until the outcome is known.
- Never automatically replay a write after a failure or restart; the user retries.
- Never label partial, stale, or failed data as live or complete.

## Docs and specs

- Specs: `docs/specs/YYYY-MM-DD-<topic>-design.md`, indexed in `docs/specs/README.md`.
  Plans: `docs/plans/YYYY-MM-DD-<topic>.md`. These locations override any tool default.
- New specs start from `docs/specs/_template.md` with `status: proposed`. Only the human
  moves a spec to `approved`.
- After implementation and before opening or updating its PR, run `spec-lifecycle`;
  `node scripts/check-specs.mjs --dir docs/specs` must pass.
- An overturned design gets a new spec that supersedes the old one; never delete a spec.
- Before adding push notifications or an app extension, read
  `docs/agents/push-and-extensions.md`.

## Checks

- Before commit: `pnpm check` (lint, typecheck, i18n, specs) and `pnpm format` on changed
  files. `pnpm test` when behavior changes; `pnpm bundle` when the build can change; a
  Simulator build when native code changes.
- All user-visible text goes through `t()`; add zh-Hans and en together.
- Tests assert behavior, not implementation snapshots or mock call counts. They are
  deterministic: fake timers and injected clocks; no real sleeps or network.
- UI changes add or update a check under `ui-checks/`, run `pnpm ui-verify` in light
  and dark, and cover shared controls in every host screen. Checks run offline; Debug
  scenes use production components and inject outcomes at `src/services` only.
- Screenshots for state, video for motion; missing scenes and timeouts fail.
  Screenshots alone do not prove correctness; compare against HIG and the last build.
- `pnpm ui-verify` owns its Simulator and build directory: never create simulators,
  pass another `-derivedDataPath`, or copy the checkout elsewhere.
- Report skipped checks and why.

## Conventions

- Conventional Commits with scope: `feat(<area>): ...`, `fix(<area>): ...`.
- Do not nest ternaries: one `a ? b : c` is fine, a `?` inside either branch is not. Map
  closed sets with an object; use `if` or `switch` for ordered conditions.
- Files under 500 lines, components under 300.
- Generated resources keep their dependency licenses beside them.
