# expo-ios-starter

- Template for iOS apps built with Expo and one Swift kit module. iOS only; never Android.
- Stack: Expo SDK 57 (Expo Router, Expo Modules), React Native 0.86, TypeScript, pnpm
  workspace, vitest. Minimum iOS 26.0; Xcode 26.4 or later. Read the versioned docs of
  the installed Expo / React Native release before writing code; do not rely on memory.
- Lint: `expo lint` (ESLint 9 flat config from `packages/config/eslint.js`, which also
  enforces the native-import and `packages/core` boundaries). Format: Prettier.

## Boundaries

- iOS only. Do not add Android implementations, fallback stubs, or Android build scripts.
- All first-party native code and native UI live in `apps/mobile/modules/starter-kit`,
  registered through `StarterKitModule`. Do not create separate bridge packages.
- App code imports native APIs only from `modules/starter-kit/src/index.ts`; never call
  `requireNativeModule` elsewhere. Remove every event subscription in effect cleanup.
- When React Native cannot meet a UI requirement at system quality, implement it in Swift
  in the kit. Never imitate a control the platform provides; the Human Interface
  Guidelines are the acceptance standard.
- Every tab owns its own Stack and uses the native navigation bar; do not draw custom headers.
- A screen that returns a result is a `definePage` page opened with `present()`. Params
  stay in the presentation store; the URL carries only `presentationId`. Every
  presentation settles exactly once.
- `ios/` is generated by prebuild and is not committed. Persist native changes in
  `app.config.ts`, config plugins, or the kit.
- Never disable code signing (`CODE_SIGNING_ALLOWED=NO` and similar), including Simulator builds.
- Credentials live in the Keychain only. Never commit tokens, certificates, or `.env` files.
- Before destructive operations (revert, reset, delete, force-push), inspect the working
  tree and ask for confirmation.

## Layout

- `apps/mobile/src/app`: routes only; screens stay thin.
- `apps/mobile/src/lib/presentation`: React bindings for `present()`.
- `apps/mobile/src/services`: the only place that talks to the outside world; verify
  mode swaps it for fixtures.
- `apps/mobile/src/theme/tokens.ts`: colors, spacing, radii, type. Screens never use raw values.
- `apps/mobile/locales/{zh-Hans,en}.json`: all user-visible text.
- `packages/core`: platform-neutral TypeScript. Must not import React Native, Expo, or `apps/*`.
- `packages/config`: shared tsconfig and lint config.

## Docs and specs

- Specs: `docs/specs/YYYY-MM-DD-<topic>-design.md`, indexed in `docs/specs/README.md`.
  Plans: `docs/plans/YYYY-MM-DD-<topic>.md`. These locations override any tool default.
- New specs start from `docs/specs/_template.md` with `status: proposed`. Only the human
  moves a spec to `approved`.
- After implementation and before opening or updating its PR, run `spec-lifecycle`;
  `node scripts/check-specs.mjs --dir docs/specs` must pass.
- An overturned design gets a new spec that supersedes the old one; never delete a spec.

## Checks

- Before commit: `pnpm check` (lint, typecheck, i18n, specs) and `pnpm format` on changed files.
- `pnpm test` when behavior changes; `pnpm bundle` when the build can change.
- All user-visible text goes through `t()`; add zh-Hans and en together.
- UI changes add or update a check under `ui-checks/` and run `pnpm ui-verify` in light
  and dark; screenshots for state, video for motion. Missing scenes and timeouts fail.
- Verify mode is fully offline: fixtures replace `src/services` only, never screens.
- Tests are deterministic: fake timers and injected clocks; no real sleeps or network.
- Report skipped checks and why.

## Conventions

- Conventional Commits with scope: `feat(<area>): ...`, `fix(<area>): ...`.
- Files under 500 lines, components under 300.
